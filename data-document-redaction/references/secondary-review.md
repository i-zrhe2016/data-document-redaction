# 文档完成后的二次审查

二次审查是对首轮脱敏或清理结果的交付前质量门，不是首轮变换的重复执行。审查者要重新建立证据链，回答两个问题：

1. 声明需要移除或抑制的内容，在候选副本的所有相关表面上是否仍不可见、不可搜索、不可复制或不可提取？
2. 副本是否仍满足已声明的业务效用和结构要求？

## 输入与边界

优先接收以下内容：

- 候选交付文件或目录；
- 首轮处理报告、变换清单、禁止实体/词表和验收标准；
- 可选的原件或基线统计。原件只能在获授权的本地环境中用于哈希、结构、计数和分布比较，不把原文载入上下文，不把原值写入报告。

二次审查阶段默认只读，不覆盖候选文件，不删除原件，不上传第三方服务。若发现问题且用户要求修复，应先生成新的输出副本，再重新执行完整复核；不要在报告阶段直接“顺手修正”。

## 独立性要求

至少组合两条不同证据路径，并记录它们的工具/版本：

- 与生成工具不同的解析器或读取路径；
- 应用级读取与原始容器/XML/对象级扫描；
- 文本抽取/搜索与独立渲染后的视觉检查；
- 第二套规则、词表或检测器。

只重复执行首轮命令，不能算独立证据。无法取得第二条路径时，结论最高只能是 `needs_review`，并说明缺口。

## 最小复核步骤

### 1. 锁定范围和版本

记录目的、接收者、允许保留的效用、敏感实体类别、候选文件路径/类型/大小/SHA-256 和验证时间。确认候选文件是新路径，原件未被覆盖；把首轮报告中的声明与实际检查项逐项对齐。

### 2. 独立提取和检测

用不同解析路径重新提取文本、表格、XML、对象和元数据，然后检查：

- 首轮禁止词、精确值及其大小写、标点、空格、连字符、昵称、缩写、分词和 OCR 变体；
- PII、凭据、令牌、URL 参数、编码后的值以及领域词典中的自由文本；
- 同一实体在正文、表格、页眉页脚、备注、图片、日志、压缩包和重复副本中的出现。

不要把匹配值打印到终端、日志或报告；只记录实体类型、表面、页码/行号类别、计数和检测器。

### 3. 检查隐藏表面

按 [document-surfaces.md](document-surfaces.md) 选择格式相关检查。特别关注首轮自动化容易漏掉的 logo/图像、重复页眉、部分文本、扫描件 OCR 层、批注/修订、文档属性、书签、链接目标、嵌入附件、隐藏工作表、备注页、文件名和增量历史。

### 4. 做视觉和交互验证

对视觉文档渲染页面并检查遮盖区域、裁切、旋转、表格、图像和重复页面。高敏感或扫描件文档应逐页检查；低风险文档可以按风险抽样，但要记录抽样覆盖率和未检查页面。至少进行全文搜索、选择/复制、文本抽取和重新打开测试。发现黑框、标注或图层只是覆盖而非删除时，不能判定通过。

### 5. 检查效用和完整性

根据用途选择必要的后置条件：文件可打开、页数/版式、文本可读性、schema、行数、主外键、唯一性、公式、空值率、分布、偏斜、异常值和跨表关联。若首轮使用真实数据的掩码副本，重点验证关系与分布没有被破坏；若用途允许，优先建议合成数据。

### 6. 结论与处置

- `pass`：声明范围内的敏感内容检查、隐藏面、视觉检查和必要的效用检查均有证据通过。
- `needs_review`：有残留匹配、漏检风险、人工覆盖不足、未清理的非关键元数据、效用偏差，或独立性不足。
- `blocked`：文件损坏/加密、关键表面无法读取、OCR 置信度过低、签名/嵌入对象无法判断，或权限/依赖导致无法完成关键检查。

每个发现写明严重级别（`blocker`/`high`/`medium`/`low`）、位置类别、影响、证据摘要和下一步；不写原值、完整上下文、映射、密钥或可用凭据。报告模板见 [output-report.md](output-report.md)。

## 本 skill 的本地基线工具

如果与生成路径不同，可运行：

```bash
python scripts/scan_sensitive.py <候选文件或目录> --pretty
python scripts/verify_pdf.py <候选 PDF> --term-file <本地禁止词文件> --pretty
```

它们只输出类型、位置和计数，适合作为基线证据；无法解析的文件、图像像素、OCR 置信度和视觉覆盖仍需独立人工或格式感知工具检查。`verify_pdf.py` 的 `pass` 只代表所请求的后置条件通过，不代表绝对安全。
